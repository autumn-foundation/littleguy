# Build features

Each integration of littleguy is a cargo feature. A build without a
feature compiles none of its code and links none of the crates it adds.

`lg` builds with the default set:

```sh
cargo install --path crates/littleguy                       # the default set
cargo install --path crates/littleguy --features full       # every integration
cargo install --path crates/littleguy --no-default-features --features discord,claude
```

A config section that needs a feature that the build leaves out stops
`lg serve` at start, and the error names the feature:

| Config | Feature |
|---|---|
| `[[camel.route]]` | `camel` |
| `[san_mateo]` | `oauth` |
| `[google]` | `google` |
| `[[mcp.server]]` | `mcp` |
| `[sandbox]` | `sandbox` |
| `--model claude` | `claude` |
| `--model openai`, `--model openrouter` | `openai` |

A Discord or Slack token of a service that the build leaves out logs a
warning. The web tools log that they are off.

## What each feature adds

The tables below come from the `[features]` section and the comments of
each `Cargo.toml`. "Crates it adds" lists the optional crates that the
feature turns on, through the features it turns on in other workspace
crates. `crate/feature` names a feature of an outside crate.
`cargo xtask feature-docs` fails in CI when a table differs from the
manifests. `cargo xtask feature-docs --write` renders them again.

## The build matrix

`cargo xtask features` runs clippy on every target of each crate with no
features, with each feature alone, and with all features, warnings
denied. Then it runs the tests of each crate with no features. The
`features` job of CI runs it. The other jobs build with all features, so
the tests and the coverage reach each integration.
